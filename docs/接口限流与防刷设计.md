# 接口限流与防刷设计

> 落地日期：2026-07-27  
> 目标：保护搜索、评论、登录、浏览量等高频入口，避免恶意请求把 ES、MySQL 或 Redis 打爆。

## 1. 设计思路

本次没有把限流逻辑写死在业务代码里，而是抽成统一组件：

```text
Controller 方法
    ↓
@RateLimit 声明限流规则
    ↓
RateLimitAspect 解析 IP / 用户 / 参数维度
    ↓
Redis Lua 原子计数
    ↓
通过：执行业务
超限：返回 code=429
```

这样后续新增接口时，只需要给 Controller 方法加注解，不需要复制粘贴防刷代码。

## 2. 核心能力

- 固定窗口限流：用 Redis 记录窗口内请求次数。
- Lua 原子执行：`INCR` 和 `EXPIRE` 在同一脚本里完成，避免并发计数不准。
- 多维度 key：
  - IP
  - 登录用户
  - 参数
  - IP + 参数
  - 登录用户 + 参数
- 同一接口可叠加多个规则。
- Redis 异常时 fail-open：限流组件故障不阻断主业务。
- Redis key 中对身份信息做 hash，避免直接暴露用户名、评论内容等敏感信息。

## 3. 已接入入口

| 入口 | 限流规则 | 目的 |
| --- | --- | --- |
| 前台搜索 | IP 每分钟 120 次；同 IP + keyword 每分钟 30 次 | 防止恶意搜索拖垮 ES，尤其是不存在关键词反复查询 |
| 评论发布 | 用户每分钟 10 次；IP 每分钟 30 次；同用户+相同内容 30 秒 1 次 | 防刷屏、防重复提交 |
| 前台登录 | IP 每 5 分钟 20 次；username 每 5 分钟 8 次 | 降低爆破风险 |
| 后台登录 | IP 每 5 分钟 15 次；username 每 5 分钟 5 次 | 管理端更严格防护 |
| 浏览量接口 | IP 每分钟 300 次；同 IP + articleId 每分钟 20 次 | 防止脚本刷浏览量接口 |

## 4. 验证记录

- `RedisFixedWindowRateLimiterTest`：验证 Redis Lua 返回 1 时放行、返回 0 时拦截、非法配置会失败。
- `mvnw.cmd -pl yan-framework -am "-Dtest=RedisFixedWindowRateLimiterTest,CacheClientTest" "-Dsurefire.failIfNoSpecifiedTests=false" test`：通过，7 个测试全绿。
- `mvnw.cmd -pl yan-admin -am -DskipTests package`：通过。
- 真实接口验证：后端启动后，对 `/api/admin/auth/login` 使用同一用户名连续错误登录 6 次，第 6 次返回 `code=429`。

## 5. 后续增强

1. 登录失败专用计数：当前限制的是登录尝试次数；后续可以改为只统计失败次数，成功登录后清理失败计数。
2. 动态规则配置：把注解中的固定阈值抽到配置中心或数据库，后台可调整。
3. 滑动窗口/令牌桶：固定窗口实现简单，后续高精度场景可升级。
4. 风控联动：对异常 IP 加入短期黑名单，配合验证码、人机校验和后台告警。
